================================
EJEMPLOS DE USO - REGISTRO Y LOGIN

================================

}

================================
5. CREAR UNA PERSONA (SIN CREDENCIALES)
================================

POST http://localhost:3000/api/personas
Authorization: Bearer <token>
Content-Type: application/json

{
  "tipo_documento": "CC",
  "numero_documento": "9876543210",
  "nombres": "María",
  "apellidos": "López",
  "telefono": "+57 301 9876543",
  "correo": "maria.lopez@email.com"
}

================================
6. CREAR CREDENCIALES PARA UNA PERSONA EXISTENTE
================================

POST http://localhost:3000/api/credenciales
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "id_persona": "uuid-de-persona",
  "id_rol": "uuid-de-rol",
  "usuario": "marialopez",
  "contrasena": "Password456!",
  "firebase_uid": null
}

================================
7. BUSCAR PERSONA POR DOCUMENTO
================================

GET http://localhost:3000/api/personas/documento/1234567890
Authorization: Bearer <token>

================================
NOTAS IMPORTANTES
================================

1. Todos los endpoints excepto register y login requieren autenticación

2. El token se puede enviar de dos formas:
   - Cookie: authToken=<token>
   - Header: Authorization: Bearer <token>

3. Roles y permisos:
   - administrador: Acceso total
   - empleado: Acceso a personas, médicos, citas
   - medico: Acceso a sus propias citas y pacientes
   - paciente: Acceso a sus propias citas

4. Los UUIDs son generados automáticamente por PostgreSQL

5. Las contraseñas se hashean con bcrypt (10 rounds)

6. Firebase es opcional - si falla la creación de usuario en Firebase,
   el registro continúa sin firebase_uid
