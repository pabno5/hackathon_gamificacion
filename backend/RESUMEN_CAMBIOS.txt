================================
SCHEMA DE BASE DE DATOS
================================

Tablas creadas:
1. personas           - Datos personales básicos
2. roles              - Roles del sistema
3. credenciales       - Usuarios y contraseñas
4. medicos            - Médicos del sistema
5. especialidades     - Especialidades médicas
6. medico_especialidad - Relación N:N médico-especialidad
7. documentos         - Documentos adjuntos
8. citas              - Citas médicas

Relaciones:
- credenciales → personas (N:1)
- credenciales → roles (N:1)
- medicos → personas (1:1)
- medico_especialidad → medicos (N:1)
- medico_especialidad → especialidades (N:1)
- documentos → personas (N:1)
- citas → personas (paciente) (N:1)
- citas → medicos (N:1)

================================
AUTENTICACIÓN
================================

Flujo anterior (solo Firebase):
1. Usuario se registra con email/password en Firebase Auth
2. Firebase genera ID Token
3. Backend verifica ID Token
4. Datos en Firestore

Flujo actual (híbrido):
1. Usuario se registra con username/password
2. Datos de persona se guardan en PostgreSQL
3. Credenciales se guardan en PostgreSQL (password hasheado)
4. Opcionalmente se crea usuario en Firebase Auth
5. Login valida contra tabla credenciales (PostgreSQL)
6. Si hay firebase_uid, genera Firebase Custom Token
7. Token se usa para autorización en endpoints

Ventajas:
✅ Control total de autenticación en tu base de datos
✅ Puedes usar username en lugar de solo email
✅ Flexibilidad para agregar campos personalizados
✅ Firebase solo se usa para tokens JWT (opcional)

================================
ENDPOINTS MODIFICADOS
================================

POST /api/auth/register
- Ahora requiere más campos (persona + credencial)
- Crea registro en personas y credenciales
- Ya no requiere solo email

POST /api/auth/login
- Ahora usa usuario + contraseña
- Valida contra tabla credenciales
- Retorna customToken de Firebase (si existe firebase_uid)

GET /api/auth/profile
- Consulta desde PostgreSQL
- Incluye información completa de persona y rol

================================
MIGRACIONES NECESARIAS
================================

Si tenías datos en Firestore, necesitarás:

1. Exportar datos de Firestore
2. Transformar formato (Firestore → PostgreSQL)
3. Importar a PostgreSQL usando scripts SQL

No hay script automático de migración, deberás hacerlo manualmente
según tus datos específicos.
